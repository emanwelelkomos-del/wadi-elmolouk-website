# مطعم وكافيه وادي الملوك — الموقع (نسخة Supabase مستقلة)

هذا المشروع موقع ثابت (HTML/CSS/JS بدون أي أداة بناء) متصل بقاعدة بيانات
وتخزين Supabase حقيقيين. لا يعتمد على أي شيء خاص بـ Claude أو Artifacts —
يمكن رفعه على GitHub ثم Vercel وربطه بدومين خاص بالمطعم مباشرة.

## ما المطلوب منك بالضبط

فقط 3 حسابات/خطوات، ولا شيء غيرها:

1. حساب Supabase (مجاني) ومشروع جديد فيه.
2. تشغيل ملفين SQL جاهزين (نسخ ولصق — لا تحتاج كتابة كود).
3. إنشاء مستخدم واحد (أنت، كمدير) داخل Supabase Authentication.

بعدها تعطيني/تضع بنفسك في `js/config.js`:
- **Project URL** الخاص بمشروعك
- **anon / public key** الخاص بمشروعك

(هذان ليسا سرّين — الحماية الحقيقية تأتي من RLS Policies الموجودة في
`sql/schema.sql`، وليس من إخفاء هذا المفتاح.)

**لن تحتاج أبدًا لإعطاء أحد الـ `service_role` key** — هذا المفتاح سرّي
تمامًا ولا يوضع في كود الموقع إطلاقًا.

---

## خطوة 1 — إنشاء مشروع Supabase

1. افتح https://supabase.com وسجّل حساب (مجاني).
2. أنشئ مشروعًا جديدًا (New Project) — اختر اسمًا وكلمة مرور لقاعدة
   البيانات (احتفظ بها، لن تحتاجها في الموقع نفسه لكن قد تحتاجها لاحقًا).
3. انتظر دقيقة أو اثنتين حتى يجهز المشروع.

## خطوة 2 — تشغيل السكريبت الأول: إنشاء الجداول

1. من القائمة الجانبية: **SQL Editor** → **New query**.
2. افتح ملف `sql/schema.sql` من هذا المشروع، انسخ محتواه بالكامل، الصقه،
   واضغط **Run**.
3. هذا ينشئ الجداول الستة (`restaurant_settings`, `menu_categories`,
   `menu_items`, `gallery`, `offers`, `opening_hours`)، يفعّل Row Level
   Security مع سياسات القراءة العامة والكتابة للمدير فقط، وينشئ Storage
   bucket عام اسمه `wadi-images` لرفع الصور.

## خطوة 3 — تشغيل السكريبت الثاني: نقل البيانات الحالية

1. **SQL Editor** → **New query** مرة أخرى.
2. انسخ محتوى `sql/seed.sql` بالكامل، الصقه، واضغط **Run**.
3. هذا ينسخ كل المنيو والأسعار والأقسام الموجودة فعليًا في الموقع
   الحالي (٨٣ صنف، ١٠ أقسام) بالإضافة لنص الصفحة الرئيسية وبيانات
   التواصل، حرفيًا كما هي — لا شيء تمت إضافته أو اختراعه.

> شغّل السكريبتين مرة واحدة فقط. إذا احتجت إعادة التشغيل لاحقًا لأي سبب،
> راجع أولًا حتى لا تتكرر بيانات المنيو.

## خطوة 4 — إنشاء حساب المدير (تسجيل الدخول للوحة التحكم)

لوحة التحكم الآن تستخدم Supabase Authentication الحقيقي بدل كلمة مرور
ثابتة داخل الكود:

1. **Authentication** → **Users** → **Add user** → **Create new user**.
2. ضع بريدك الإلكتروني وكلمة مرور قوية.
3. هذا هو الحساب الذي ستدخل به إلى لوحة التحكم في الموقع.
4. لتغيير كلمة المرور لاحقًا: من نفس الصفحة، اختر الحساب ثم
   **Reset password** أو أرسل رابط تعيين كلمة مرور لبريدك.

لا يوجد تسجيل عام (Sign up) في الموقع — فقط أنت من يملك حسابًا، ويُنشأ
يدويًا من هنا فقط.

## خطوة 5 — الحصول على المفتاحين ووضعهما في الموقع

1. **Project Settings** (أيقونة الترس) → **Data API**.
2. انسخ **Project URL**.
3. انسخ **anon public key** (وليس `service_role`).
4. افتح ملف `js/config.js` في هذا المشروع وضع القيمتين مكان:
   - `PASTE_YOUR_SUPABASE_PROJECT_URL_HERE`
   - `PASTE_YOUR_SUPABASE_ANON_PUBLIC_KEY_HERE`
5. احفظ الملف.

## خطوة 6 — تجربة الموقع محليًا (اختياري لكن يُنصح به)

افتح `index.html` مباشرة في المتصفح، أو شغّل خادمًا محليًا بسيطًا، مثلًا:

```
npx serve .
```

ثم افتح الرابط الذي يظهر. جرّب:
- تصفح الموقع وتأكد إن المنيو والصور تظهر.
- اضغط "لوحة تحكم المطعم" في الفوتر، سجّل الدخول بالحساب الذي أنشأته.
- جرّب: تعديل نص، إضافة صنف، رفع صورة، حذف صنف، تسجيل خروج.
- أعد تحميل الصفحة (Refresh) وتأكد إن كل شيء لسه موجود.

## خطوة 7 — النشر على Vercel

1. ارفع هذا المجلد بالكامل إلى مستودع GitHub جديد.
2. من https://vercel.com → **Add New Project** → اختر المستودع.
3. نوع المشروع: **Other / Static** (لا يوجد Build Command مطلوب — هو
   ملفات ثابتة).
4. اضغط Deploy.
5. بعد نجاح النشر، من إعدادات المشروع في Vercel أضف الدومين الخاص
   بالمطعم (Domains → Add).

الموقع سيعمل من أي جهاز وبعد أي عدد Refresh، لأن كل البيانات والصور
أصبحت في Supabase الحقيقي، وليست مرتبطة بهذا الـ Chat أو بمتصفح معيّن.

## هيكل الملفات

```
index.html              الصفحة الرئيسية (تحمّل كل الملفات التالية)
css/style.css           كل تنسيقات الموقع (نفس التصميم الحالي)
js/config.js            ← عدّل هذا فقط: رابط ومفتاح مشروعك
js/supabaseClient.js    طبقة الاتصال بـ Supabase (لا تحتاج تعديله)
js/app.js               منطق عرض الموقع ولوحة التحكم (لا تحتاج تعديله)
sql/schema.sql           الجداول + الحماية (RLS) + Storage — شغّله أولًا
sql/seed.sql             نقل بيانات المنيو الحالية — شغّله ثانيًا
```

## ماذا تغيّر عن النسخة السابقة

- الصور الآن تُرفع فعليًا إلى **Supabase Storage** (bucket عام اسمه
  `wadi-images`) بدل التخزين المؤقت الخاص بالمعاينة داخل Claude.
- كل بيانات الموقع (المنيو، الأسعار، الصور، مواعيد العمل، العروض،
  بيانات التواصل) أصبحت في **جداول Postgres حقيقية** في مشروعك.
- الدخول للوحة التحكم أصبح عبر **Supabase Authentication** (بريد
  وكلمة مرور حقيقيين) بدل كلمة مرور ثابتة داخل الكود.
- تمت إضافة قسم **"مواعيد العمل"** في لوحة التحكم لتعديل كل يوم على
  حدة، وقسم **"العروض"** لإضافة وتعديل وإخفاء العروض — وهما مطلبان
  كانا مذكورين سابقًا ولم يكونا مطبّقين بالكامل في النسخة القديمة.
- تمت إزالة زر "إعادة تعيين كل البيانات" من لوحة التحكم لأن قاعدة
  البيانات الآن حقيقية ومربوطة بحسابك — حذف كل شيء بضغطة واحدة غير
  مناسب لموقع فعلي منشور. إذا احتجت مسح بيانات معيّنة، احذفها يدويًا من
  Table Editor في Supabase، أو اطلب مني تعديل الكود لإضافة الميزة مرة
  أخرى بشكل أكثر أمانًا (تأكيد مضاعف مثلًا).

## ملاحظة أمنية مهمة

مفتاح `anon` في `js/config.js` مصمَّم ليكون علنيًا ويظهر في كود أي
موقع يستخدم Supabase — هذا طبيعي ومتوقّع. الحماية الفعلية هي سياسات
Row Level Security المطبّقة في `sql/schema.sql`، والتي تمنع أي شخص من
التعديل أو الحذف ما لم يكن مسجّل دخول بحساب مدير حقيقي. **لا تضع أبدًا**
مفتاح `service_role` في أي ملف داخل هذا المشروع.
